# Daily Log: 2026-09-14 - Local-First Migration: Repository Moves Off Google Drive

## 1. Decision
The working copy moves to `D:\AGENT\RAG_TEM` on local NTFS. Google Drive stops being a
working location and becomes a **one-way mirror** whose only job is to keep the Obsidian
vault readable from other devices.

## 2. Why Google Drive Cannot Be The Remote
`origin` is already `https://github.com/r1anpratama/RAG_TEM.git`, and `main` was already in
sync with it. Google Drive was never a git remote - it syncs *files*, not git objects:

- Two-way sync over `.git/` invites repository corruption. There is no merge step and no
  conflict resolution; collisions surface as `Dashboard (1).md`, `Dashboard (2).md`.
- Drive syncs mid-write, so an index and working tree can be captured in an inconsistent
  state and only fail much later.
- It is empirically unreliable here: `EBADF: bad file descriptor, write`,
  `TAR_ENTRY_ERROR UNKNOWN`, `ENOTEMPTY`, `ENOENT`, and `SetFileSecurityW EIO` all occurred
  during a single session.
- Directory junctions cannot be created on it ("Local NTFS volumes are required"), so
  `node_modules` could not be linked back to local disk either.

GitHub already provides history, atomicity, conflict handling, and off-site backup. Drive
adds none of that, so it does not belong in the loop for code.

Drive does retain one capability GitHub does not: the repository is also the Obsidian vault
(`.obsidian/`, `00_Index/`, `01_Workflows/`, ...), and a vault is pleasant to read on other
devices. That - and only that - is what the mirror preserves.

## 4. Migration Method
Copied the working tree **with** `.git` so uncommitted work survived, rather than cloning
from GitHub:

```powershell
robocopy 'G:\...\RAG_TEM' 'D:\AGENT\RAG_TEM' /E `
  /XD node_modules .next __pycache__ .pytest_cache .turbo /XF *.pyc /MT:8
```

Result: 937 files, 291.59 MB, 0 failed.

## 6. Daily Operations
```powershell
# Serve the stack (from D:\AGENT\RAG_TEM)
python -m uvicorn website.backend.app.main:app --host 127.0.0.1 --port 8000 --reload
python -m uvicorn src.api.server:app            --host 127.0.0.1 --port 8080
cd website\frontend; npm run dev                # http://localhost:3000

# Refresh the Google Drive vault mirror (one-way, local -> Drive)
pwsh -File D:\AGENT\rag-tem-drive-mirror.ps1
pwsh -File D:\AGENT\rag-tem-drive-mirror.ps1 -DryRun   # preview only
```

The mirror excludes `.git`, `node_modules`, `.next`, `__pycache__`, `.pytest_cache`,
`.turbo`, and `*.pyc`, so git internals and build output never reach Drive. It is run
on demand, not as a daemon, so Drive does not churn while work is in progress.

Python tests (run from the repository root):
```powershell
$env:PYTHONPATH=".;website/backend"; pytest
```
